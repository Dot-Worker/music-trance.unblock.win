# Music Trance

**浏览器本地的解密与音频转换工具。** 音频、数据库和用户输入的密钥不上传到转换服务器。GitHub Actions 只构建程序及运行合成样本测试，GitHub Pages 只提供静态资源。

- 站点：<https://music-trance.unblock.win/>
- 仓库：`Dot-Worker/music-trance.unblock.win`

## 输出选项

| 格式 | 选项 |
| --- | --- |
| 仅解密 / 保持原样 | 不重编码，保持解出的音频容器 |
| MP3 | 128 / 192 / 256 / 320 kbps |
| WAV | 保留音源精度，或 16-bit / 24-bit / 32-bit 浮点 |
| FLAC | 无损，保留兼容的音源精度，或明确选 16 / 24-bit |
| APE | 无损，16 / 24-bit 单声道或双声道；只开放验证过的标准压缩模式 |
| AAC / M4A | AAC-LC，目标 256 / 320 / 512 kbps，实际码率随内容变化 |

采样率默认**逐个文件跟随音源**，也可明确选择 44.1 或 48 kHz。编码器不支持所选源参数时会提示，不偷偷降采样、混缩声道或降低位深。输出规格不能恢复有损音源已经丢失的信息；无损格式的压缩级别改变体积与耗时，不改变应保留的 PCM 音频。

可逐个下载，也可打包 ZIP。输出使用独立安全名称，不覆盖原文件。当前不额外写入原加密容器的歌手、标题和封面。

## 输入与边界

支持 NCM、KGM/KGMA/VPR、旧 KWM、传统 QMC、携带 ekey 的旧 MFLAC/MGG，以及已识别的普通音频容器。QQ 新版 STag / musicex 无 ekey 时返回 `NEED_QQ_EKEY`，不伪装成功。

KGG 需要用户主动选择自己的匹配 SQLite 数据库。明文数据库合成样本已验证；有限旧 SQLCipher 布局的加密数据库支持仍为实验性，不能保证所有版本。密钥只填网页的本地密码框，不要发到聊天或提交仓库。

桌面使用目标：开始处理前建议至少约 8 GiB 可用内存；网页不会假称能够准确检测系统空闲内存。当前限额为单文件 256 MiB，队列 20 个，批次输入 512 MiB，数据库 32 MiB，ZIP 输出 256 MiB，单项中间 / 输出约 512 MiB，已完成结果合计 512 MiB。可逐项释放结果，再继续处理。接近安全上限时拒绝导出，不保存截断音频。浏览器、设备内存及源格式仍会影响可用性，手机不保证支持这些桌面额度。

只处理合法持有、有权使用的文件。不提供平台登录、在线取钥或付费授权绕过。

## 使用

1. 选择文件，或加载内置合成示例。
2. 选择输出格式、质量和采样率。
3. 点击开始；完成后逐项下载或下载 ZIP。

关闭页面前保存结果。队列、数据库、密钥和结果不写入 localStorage / IndexedDB；清空或离开页面时释放引用和 Blob URL。JavaScript 垃圾回收不等于可证明的安全擦除。

## 构建与许可

主应用改编自用户提供的 `WYYYYKG2Porsche`（Copyright © 2026 WangZhen，MIT），保留原版权声明。音频核心分别保留 FFmpeg/LAME 的 LGPL 和 Monkey’s Audio 的 BSD 许可；不把整个分发包统称为 MIT。本站提供同源许可文本和对应源码 / 重构建材料，见 [第三方说明](THIRD_PARTY_NOTICES.md)。

运行时只有静态 JS / CSS / WASM，不需要本机安装 FFmpeg，不需要处理服务器。首次加载引擎后在本地处理。

开发需要 Node.js 24、Python 3 和 Linux 构建工具；合成音频检查使用系统 FFmpeg / ffprobe。源码与工具链固定版本并校验摘要。

```sh
npm ci --ignore-scripts
npm test
npm run build:core
npm run test:wasm
npm run build:ape
npm run test:ape
npm run build
```

独立 APE 核心的构建命令及约束见 `scripts/ape/`；CI 串联所有必要构建、源码摘要和音频检查后才部署。静态产物在 `dist/`。不要提交原始上传 ZIP、签名文件、真实音乐、用户数据库、密钥、依赖目录或构建缓存。

## 验证口径

使用已知 SHA-256 的 440 Hz 合成样本验证解密，用实际 WebAssembly 编解码并检查真实容器参数。APE 在标准压缩模式下逐项进行准备后 PCM 的编码 / 解码比对，校验失败不会导出。

实际浏览器操作、底层 WASM 测试和真实用户文件兼容性分开记录。不能把构建成功当作所有浏览器、所有音乐平台版本或所有输入都通过；手机与真实用户音乐的覆盖仍有限。

### 大文件验证范围

真实 Node/Worker WebAssembly 压力测试覆盖了接近 256 MiB 输入、511 MiB WAV 输出、480 MiB PCM 的 APE 编码/回读、256 MiB ZIP，以及超限拒绝、取消和重试；独立解码的 PCM 摘要与时长一致。测试进程最高观察到约 2.6 GiB RSS（APE 路径），这不是浏览器内存保证，也不代表所有源格式的峰值。引擎线性内存上限仍为 FFmpeg 2 GiB、APE 1 GiB；没有为了放大文件限额而直接扩张堆上限。
